Filters

Offthe pixels as they are
Smooththe browser's smoothing when the picture is scaled
Scanlinesdark lines between the lines of the picture
CRTa TV tube: slightly curved screen, soft beam lines (wider where brighter), colors blurred a little across, phosphor mask on a big screen, darker corners
PALa home TV's colors: brightness sharp, color blurred across over a few pixels, so fine patterns of two colors mix into one
Scale 2xScale2x (AdvMAME): each pixel 2x2 with the corners of slopes filled: smoother edges, no blur; works without WebGL
Scale 3xthe same in 3x3 parts: finer steps on a big screen
xBRedges found and drawn as smooth lines at 30, 45 and 60 degrees at any size, no blur: the smoothest
Anti-Text64text of 4x8 letters (64 a line: the press, text viewers) recognized and drawn with 8x16 letters. Only the lines where at least half of the letters are known: other text (5-dot letters, QC panels) and pictures stay as they are, so it can stay on. Font base of UnrealSpeccy: 1090 letters, inverse too
Anti-Text42the same for 6x8 letters (42 a line). Known letters: the 48K ROM font and the 8x8 font of UnrealSpeccy (Latin, Cyrillic) cut to 6 columns, as 42-column print routines do; other fonts stay as they are
Font tables16 and more known letters in a line whose codes go up with the cells (a font table or a font editor, a letter a cell or every second one): that run, from its first letter to its last, stays as drawn by the program; the rest of the line is drawn anew: Anti-Text64 and Anti-Text42
ZXIPentagon: the ZEsarUX ZXI ports. #CF3B: register number (reads back), #DF3B: its value. Register 4: the name "WUS" (write 0 to start over, each read gives the next letter, 0 at the end), #80 bit 0 = 1: Anti-Text64 / 42 off while a program wants its own letters. Reset and loading a snapshot clear the registers
Linkfx=text64 (any filter: off, smooth, scan, crt, pal, scale2x, scale3x, xbr, text64, text42) uses that filter for this visit, the one chosen in Options stays saved
WhereCRT, PAL, Scale 2x / 3x, xBR: all models (on the machine's own pixels; CRT, PAL, Scale 3x, xBR need WebGL 2). Anti-Text: where the picture is the ZX screen (ATM, Evo, Profi, GMX in their ZX mode too; not TS-Conf, Sprinter, SAM Coupé, Next). Screenshot (F6), PNG: With filter saves the picture as the filter draws it (CRT, PAL, Scale 3x, xBR at 3 pixels a ZX pixel; Scanlines, Scale 2x, Anti-Text at the frame's size), off: the machine's own picture; Save / PNG does as F6 last chose. Smooth is the browser's and not saved

MoonSound INT

Players of MSX music (OPL4) keep tempo at 60 Hz, while ZX frame INT is 50 Hz. Options → Sound → MoonSound INT (also Options → ULA) sets where their INT comes from:

Offframe INT of machine only (50 Hz); a program made for card INT plays slower or stops
Card(default) INT jumper of ZXM-MoonSound: IRQ of OPL4 timers (FM registers 2–4) goes to Z80 INT, along with frame INT. Program sets timer (60 Hz) and clears its flag in each INT (register 4 = #80 + its bits); until then INT line stays active. For programs written for real card: moonmusic_1
Set INT ratemachine INT comes at rate set in field under list (60 Hz) instead of frame INT, but only while program keeps an OPL4 timer running with its IRQ enabled (register 4: ST1 or ST2 on, its MASK off); before that (menus, loaders, BASIC, TR-DOS) and after timer stops: frame INT. First INT comes one period after timer start. Picture and frame stay 50 Hz. For programs made for emulators without card INT: they start timer once and never clear its flag (moonmusic_1u)
Which onewith Card, a program that never clears timer flag gets INT again after every EI (hundreds per second): music too fast, notes crackle; use Set INT rate for it. A program that clears flag plays right with Card

Performance help

Live graphs, updated twice a second. Big number is current value, line below explains it.

Z80 code at

Where Z80 runs its code: 64K address space as 4 banks of 16K (page in each bank is signed), 1K blocks glow by how often program counter is there. Big number: hottest block. Below: share of time in ROM / RAM, busy = part of frame CPU is not halted.

Host

How much of real time this browser spends emulating. The solid part of the graph: the emulation (core); the light part above it: the picture (draw). Below: milliseconds of each per emulated frame (20 ms in all = real time limit).

Memory

RAM as map of 16K pages: written pages glow, pages mapped into Z80 address space now are outlined. Big number: pages written since last update.

Disk

Share of frames with floppy drive busy (reading or writing).

I/O

Z80 port accesses per frame (IN + OUT).

Frames

Emulated frames per second: 50 is real time; red above dashed line = faster than real time (Max speed, turbo).
